# Phase 5 — إدارة السجلات Add/Edit

## الحالة

بدأ التنفيذ الفعلي على فرع `phase5/record-management`. طُبقت ترقية Supabase
`phase5_attached_record_contract` في الإنتاج بالإصدار `20260901211437`، ويقابلها
الملف `supabase/migrations/041_phase5_attached_record_contract.sql`.

## توحيد attached

- نتيجة `admin_create_catalog_draft` أصبحت `status = attached` في جميع مساراتها.
- أُلغي مسار المنتج من هذه الدالة القديمة؛ المنتجات تمر حصراً عبر
  `admin_create_product_draft_v2`.
- قبول منتج وارد من بوابة الشريك يستخدم العقد نفسه.
- أزيل التحويل البرمجي الذي كان يعيد origin إلى `draft` بعد نجاح الربط.
- بقيت حالة النشر الداخلية `draft` في جداول الكتالوج لأنها حاجز مراجعة مطلوب،
  وليست نتيجة عملية الربط ولا حالة مهجورة.

## Add/Edit الذري للمنتجات

- مركز الإدخال يجلب `admin_record_contract_revision` مع بيانات التصنيف.
- إنشاء المنتج ومواصفاته ومصدره أصبح عملية ذرية واحدة عبر
  `admin_create_product_draft_v2`؛ أزيل تسلسل create ثم PATCH الذي كان قد يترك
  منتجاً ناقص المواصفات عند فشل الطلب الثاني.
- محرر المنتج يستخدم `admin_update_product_v2` لتعديل المنتج والفئة والمواصفات
  وملاحظات الجودة في معاملة واحدة.
- أي revision قديم يعيد `409 contract_revision_stale` برسالة واضحة للمستخدم.
- القيم العددية والمنطقية والتاريخية وJSON وenum وmulti-enum تُحوّل وتُفحص على
  الخادم قبل استدعاء RPC.

## فحص النظافة

- لا يوجد منتج draft بلا فئة رئيسية أو مصدر رئيسي.
- توجد 6 عروض draft، وكلها مرتبطة بمصدر؛ لذلك لم تُحذف لأنها سجلات مراجعة حقيقية.
- لم يثبت وجود جدول أو عمود إنتاجي مهجور يمكن حذفه بأمان.
- لم تُحذف الفهارس التي يعرضها Advisor كـunused؛ عمر المشروع وحجم الحركة لا
  يكفيان لإثبات أنها زائدة، وبعضها يحمي مسارات FK والبحث والوسائط.
- تحذير Security Advisor الوحيد ما زال إعداد Auth الخاص بـLeaked Password
  Protection، وليس مشكلة في migration 041.
