# حزمة تطبيق قهوتنا — FlutterFlow

## الحالة

هذه الحزمة هي مواصفة البناء القابلة للتنفيذ لتطبيق Android وiOS. الويب وقاعدة البيانات جاهزان للعقود أدناه. إنشاء ملف مشروع FlutterFlow نفسه يحتاج دعوة المالك إلى مساحة FlutterFlow؛ لا يمكن توليد ملف مشروع مملوك لحساب خارجي من المستودع.

## الشاشات

| المجموعة | الشاشات | مصدر البيانات |
|---|---|---|
| الاستكشاف | الرئيسية، البحث، القهوة، المعدات، الدليل، التعلم | واجهات `api/public-*` |
| التفاصيل | بطاقة المنتج، عرض البائع، صفحة الجهة | واجهات القراءة العامة |
| المستخدم | المفضلة، المقارنة، Coffee Finder | محلي أولاً ثم Supabase للمستخدم المسجل |
| الجهة | الدخول، نظرة عامة، طلب جديد، سجل الطلبات، ملاحظات المراجع | Supabase Auth + `organization_memberships` و`partner_submissions` |
| الدعم | مساعدة، تصحيح، مطالبة، نتيجة اختبار | واجهات الدعم والحقوق الحالية |

## الإعداد في FlutterFlow

1. ربط Supabase URL وPublishable key من إعدادات المشروع، وعدم وضع Service Role داخل التطبيق.
2. تفعيل Email/Password Auth وربط المستخدم بصف `profiles`.
3. استيراد جداول القراءة العامة، و`organization_memberships` و`partner_submissions`.
4. ضبط العربية RTL وIQD والمنطقة الزمنية `Asia/Baghdad`.
5. إضافة App State باسم `pendingPartnerActions` من نوع JSON List محفوظ محلياً.
6. عند الحفظ: إنشاء UUID ثابت للعملية، حفظها محلياً، ثم الإرسال. عند نجاح الإدخال يحذف العنصر المحلي. القيد `unique(submitted_by,idempotency_key)` يمنع التكرار.
7. لا تمنح أي Action للبائع يكتب في `products` أو `offers` أو `organizations` مباشرة.

## سياسة التزامن

- القراءة العامة تستعمل cache قصير وصوراً مصغرة، مع إعادة المحاولة عند عودة الشبكة.
- إنشاء طلب جهة يعمل Offline؛ النشر والمراجعة لا يعملان Offline.
- التعارض لا يدمج تلقائياً. إذا أصبحت الحالة `in_review` أو `approved` تنشأ مطالبة جديدة بدلاً من تعديل القديمة.
- الصور تضغط قبل الرفع، ولا يبدأ رفعها إلا مع اتصال متاح. يحتفظ التطبيق بالمسار المحلي وحالة الرفع حتى وصول تأكيد الخادم.

## بوابات القبول

- Android: اتصال ضعيف، RTL، رجوع النظام، استئناف الرفع، وإغلاق/فتح التطبيق أثناء وجود طابور.
- iOS: Safe Area، الرجوع، أذونات الصور، استئناف التطبيق، وعدم فقدان المسودة.
- الصلاحيات: مستخدم من جهة A لا يستطيع قراءة أو تعديل طلب جهة B.
- التكرار: إرسال UUID نفسه مرتين ينتج سجلاً واحداً.
- النشر: طلب البائع لا يظهر للعامة قبل اعتماد الإدارة ومروره بطابور السجل الرئيسي.

## ما يؤجل لما بعد Beta

- الدفع والطلبات المالية والتسوية والاسترداد.
- الإنجليزية كواجهة كاملة.
- مزامنة صور متعددة في الخلفية على iOS دون فتح التطبيق.
