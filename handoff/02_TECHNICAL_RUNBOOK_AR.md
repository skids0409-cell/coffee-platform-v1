# دليل التشغيل التقني

## المكونات

- واجهة متعددة الصفحات: React / Next-compatible Vinext على Cloudflare Sites.
- قاعدة البيانات والمصادقة والتخزين: Supabase Postgres/Auth/Storage.
- CMS التشغيلي: صفحة `/operations` مع طوابير المراجعة، إضافة إلى Supabase Dashboard لإدارة الحقول الكاملة.
- البحث في V1: واجهات بيانات Supabase مع بحث موحد منظم.

## متغيرات البيئة

تضبط في الاستضافة ولا تحفظ قيمها داخل المصدر:

```text
SUPABASE_URL
SUPABASE_PUBLISHABLE_KEY
```

لا يستخدم المتصفح مفتاحاً سرياً. لا تضف `service_role` إلى المستودع أو الواجهة.

## البناء والتحقق

```bash
npm ci
npm run lint
npm test
npm run validate:artifact
```

يتطلب المشروع Node.js 22.13 أو أحدث. نجاح الأوامر لا يغيّر بيانات Supabase ولا يفعّل الإطلاق العام.

## ترتيب قاعدة البيانات

شغّل ملفات `supabase/migrations` بالترتيب الرقمي عند إنشاء مشروع جديد. لا تعِد تشغيل ملفات الاستيراد على قاعدة حية قبل قراءة تعليقات السلامة داخل كل ملف. النسخة الحالية من قاعدة المالك نُفذت عليها الملفات `001`–`010`.

## النشر

1. شغّل الاختبارات.
2. راجع الفرق البرمجي والبيانات.
3. أنشئ نسخة نشر خاصة غير قابلة للفهرسة.
4. تحقق من حالة النشر والرابط.
5. نفذ خطة الفحص الواقعي.
6. لا توسع الجمهور ولا تغير `public_launch_enabled` قبل توقيع قائمة القبول.

## الاستعادة

- ارجع إلى آخر نسخة نشر ناجحة من الاستضافة.
- لا تستخدم حذفاً شاملاً للبيانات.
- استخدم الأرشفة أو إعادة الحالة إلى `in_review` للسجلات المنشورة خطأً.
- راجع `audit_events` لمعرفة من غيّر السجل ومتى.
